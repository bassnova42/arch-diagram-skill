# RokoAI arch-diagram · Architecture Diagram Skill

Works with **Claude Code** and **Codex**.

Give it a GitHub repo, a technical article, a PDF or a local project. Claude Code or Codex reads the structure and draws an architecture diagram: a dark "terminal blueprint" by default, or one of seven other themes (see [Themes](#themes)). Packets flow along the wires, and the log at the bottom adds a line in real time whenever two modules exchange data.

**Below: the architecture of the open-source project [morluto/rea](https://github.com/morluto/rea), generated by this skill from its GitHub repo:**

![morluto/rea architecture](examples/rea.gif)

More examples (an article, a GitHub repo, a requirements doc) are in [Examples](#examples) at the end.

## What it does

- **Structure fitted to the content**: layered system, pipeline, process with loops, hub and spoke, swimlanes or hierarchy. No fixed template.
- **Colors that mean something**: boxes are colored by kind; wires are colored and dashed by flow type (request, write, callback, async…); group frames show containment.
- **Live trace log**: when a packet reaches the end of a wire, a line `time · type · A → B · detail` is added at the bottom.
- **Self-check**: headless Chrome checks for overlapping boxes, overflowing text, wires through boxes and covered labels, and Claude fixes them until the layout is clean.
- **Eight themes**: Night Terminal, Blueprint, Drafting Paper, Whiteboard Sketch, Bold Brutal, Phosphor CRT, Soft Cards and Iso Sandbox, switched with one sentence.
- **Many outputs**:
  - Interactive single-file HTML
  - PNG (2× resolution)
  - MP4: 20 seconds by default, any length on request, a seamless 4-second loop
  - GIF: one loop
  - Mermaid flowchart

## The diagram speaks your prompt's language

The diagram is written in the language you use to ask for it:

- Write the prompt in **English** and the whole diagram is in English
- Write it in **Chinese** and titles, descriptions, labels and the log are in Chinese
- Write it in **Japanese** and all of the content is in Japanese

This holds even when the source article or code is in another language. Code identifiers, paths and commands stay as they are. Interface words such as legends and status labels are built in for Chinese, English, Japanese, Korean, Spanish and Thai; for other languages Claude writes them in your language.

## Install

Needs Node ≥ 18 and Chrome, Chromium or Edge. Video and GIF output also need `ffmpeg` (`brew install ffmpeg`).

**Option 1: npm** (simplest)

```bash
npx @rokoai/arch-diagram install
```

This installs to `~/.claude/skills/arch-diagram`. Add `--project` to install into the current project's `.claude/skills/`. Run it again to update; remove it with `npx @rokoai/arch-diagram uninstall`.

If Codex is installed (`~/.codex` exists), it is installed to `~/.codex/skills/arch-diagram` as well. Add `--claude` or `--codex` to install for only one of them.

> Running `npx @rokoai/arch-diagram …` from inside a clone of this repository fails with `arch-diagram: command not found`: npm resolves the package to the checkout itself and does not put its command on PATH. Run it from another directory, or inside the checkout use `node bin/cli.mjs install` (same flags, e.g. `--codex`).

**Option 2: plugin**. In Claude Code, run:

```
/plugin marketplace add bassnova42/arch-diagram-skill
/plugin install arch-diagram@arch-diagram
```

In Codex CLI:

```bash
codex plugin marketplace add bassnova42/arch-diagram-skill
codex plugin add arch-diagram@arch-diagram
```

**Option 3: copy by hand**

```bash
git clone https://github.com/bassnova42/arch-diagram-skill
cp -R arch-diagram-skill/skills/arch-diagram ~/.claude/skills/
cp -R arch-diagram-skill/skills/arch-diagram ~/.codex/skills/   # Codex
```

Restart Claude Code or Codex after installing.

## Usage

Just ask in Claude Code or Codex, for example:

- `Draw the architecture of https://github.com/plausible/analytics`
- `Turn this article into a flowchart: <URL>, export a 30-second video`
- `Export that diagram as an image` / `as mermaid`
- To call the skill explicitly: `/arch-diagram <repo or article URL>` in Claude Code, `$arch-diagram <repo or article URL>` in Codex

Each diagram's source is `<slug>.spec.json`. To change a diagram, ask Claude Code or Codex to edit the spec and rebuild. You can also use the command line directly:

```bash
npx @rokoai/arch-diagram build  my.spec.json my.html
npx @rokoai/arch-diagram check  my.html
npx @rokoai/arch-diagram export my.html my.png my.mp4 --seconds 30
```

## Themes

The default is **Night Terminal** (`terminal`), and there are seven more themes. Name a style in your request, e.g. `draw it as a blueprint`, `use the whiteboard style`, `make it isometric`; with no style named you get the default.

- **Only the look changes**: the same spec renders in every theme. Switching never touches structure, text or coordinates, and the self-check is the same. An existing diagram can be redrawn with one sentence: "switch it to Soft Cards".
- **Colors keep their meaning**: every theme has its own palette, but blue, cyan, green, amber and purple still mark the same kinds of element, so the legend reads the same.
- **Every output works**: HTML, PNG, MP4 and GIF export in every theme (Mermaid is laid out by Mermaid itself and has no theme).

```bash
npx @rokoai/arch-diagram build my.spec.json my.html --theme whiteboard
```

The seven new themes in detail. Each example is the [morluto/rea](https://github.com/morluto/rea) diagram, the same spec as the one at the top of this page.

### Blueprint · `blueprint`

![Blueprint](themes/blueprint.gif)

- **Look**: White ink on blueprint blue over a 20px / 100px grid, inside a double sheet frame. Registration crosses on every box corner, italic wire labels, long dashes for async wires. The palette shifts to pale tints so the colors still separate on blue.
- **Best for**: Design reviews, technical proposals, anything that should feel like an engineering drawing.
- **Ask for it**: `draw it as a blueprint` · `blueprint style`

[▶ 20-second video (MP4)](themes/blueprint.mp4)

### Drafting Paper · `drafting`

![Drafting Paper](themes/drafting.gif)

- **Look**: Ink on aged drafting paper with grain, serif type and a double sheet frame. Every component gets a numbered balloon on its top-left corner so you can walk through it item by item; wires start with a dot and async wires are dash-dot.
- **Best for**: Print, PDF export, manuals and paper figures, or any walkthrough by item number.
- **Ask for it**: `technical drawing style` · `drafting style` · `make it look like a manual`

[▶ 20-second video (MP4)](themes/drafting.mp4)

### Whiteboard Sketch · `whiteboard`

![Whiteboard Sketch](themes/whiteboard.gif)

- **Look**: Marker on a white board: slightly wobbly outlines, hatched color fills, open pen-stroke arrowheads and a highlighter swipe under the title. The wobble uses a fixed seed, so every render is identical and videos still loop seamlessly.
- **Best for**: Brainstorms, early design discussions, explaining to non-engineers, blog illustrations.
- **Ask for it**: `hand-drawn` · `whiteboard style` · `sketch it`
- **Note**: Looks most hand-written with a handwriting font installed (LXGW WenKai, Hannotate, Chalkboard SE…); without one the text falls back to the system font and the strokes stay hand-drawn.

[▶ 20-second video (MP4)](themes/whiteboard.mp4)

### Bold Brutal · `brutalism`

![Bold Brutal](themes/brutalism.gif)

- **Look**: Cream background, 2px black outlines with 6px hard shadows, loud flat fills in each element's color, heavy type. Thick wires, labels on white tags with black borders, the title on a black block.
- **Best for**: README heroes, social posts, slides and posters, anywhere it has to grab attention at first glance.
- **Ask for it**: `brutalist style` · `make it bold` · `poster look`

[▶ 20-second video (MP4)](themes/brutalism.mp4)

### Phosphor CRT · `crt`

![Phosphor CRT](themes/crt.gif)

- **Look**: A black-green tube: glowing phosphor text and wires, double-ruled boxes, scanlines and vignette over the page, a `>` prompt before the title.
- **Best for**: Security, reverse engineering and infrastructure topics, retro talks, video thumbnails.
- **Ask for it**: `retro terminal` · `CRT style` · `phosphor green`

[▶ 20-second video (MP4)](themes/crt.mp4)

### Soft Cards · `saas`

![Soft Cards](themes/saas.gif)

- **Look**: Light dot-grid background, white rounded cards with a thin colored top accent and soft shadows. Rounded wire corners, pill-shaped labels, dotted async wires.
- **Best for**: Product docs, landing pages, external overviews and light documentation sites (Notion, Confluence…).
- **Ask for it**: `clean light style` · `product docs style` · `SaaS style`

[▶ 20-second video (MP4)](themes/saas.mp4)

### Iso Sandbox · `isometric`

![Iso Sandbox](themes/isometric.gif)

- **Look**: The finished, self-checked layout is laid on an isometric floor grid, and every box becomes a block with depth and a floor shadow. Header, legend and log stay upright. The canvas widens (about 1.5×) instead of shrinking the text.
- **Best for**: Covers, promo images, overviews of systems with few components.
- **Ask for it**: `3D style` · `isometric` · `make it 3D`
- **Note**: Text tilts with the floor, so it reads best with up to about 12 nodes; for dense diagrams pick another theme.

[▶ 20-second video (MP4)](themes/isometric.mp4)

## Layout

```
skills/arch-diagram/
  SKILL.md            workflow: read source → choose structure → lay out → self-check → export
  assets/             rendering engine, styles, template; themes/ holds one stylesheet per theme
  scripts/            build / check / export
  references/         spec fields, visual style
  examples/           rea (repo), plausible (repo), elephant-goldfish (article)
bin/cli.mjs           npm commands: install / uninstall / build / check / export
```
